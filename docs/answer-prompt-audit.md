## 调用组成

1. 报告生成：`services/report.ts` 用 `reportPrompt` 拼接任务指令、JSON格式、可选指标规则、输入数据及可选校验反馈。输入数据现在只包含原始 `idea`，以及每篇文章的 `id/evidence`；证据只含编号和正文。已删除原先传入的来源标题、网址和类别，作者等额外元数据也不会被序列化。来源信息留在后台供页面展示。证据来自提取正文，每篇取前 25,000 字符中的候选段落，按问题相关性排序，约 7,000 字符预算；不是整篇全文，也不是搜索摘要。没有对话历史或社交写作示例。
2. 本地校验：引用编号映射为原文 `quote`，程序检查引用来源、正文片段和数字锚点。通过后直接完成报告，不再调用模型做语义复核；补写后的回答同样只做本地校验。原语义复核的服务、提示词和节点已删除。
3. 社交文案：输入是页面核心观察正文、写作风格示例、目标长度及可选纠错反馈。这一阶段没有接收原始问题和文章正文。其中的 AI4AI 示例只影响社交文案，不在报告生成输入中，不能用来解释截图中的固定文案。按用户要求，本次只收敛核心回答输入，社交文案提示词及参考示例保持原样。
4. 供应商：`providers/qwen.ts` 将以上字符串作为 `/responses` 的 `input`，默认模型为 `qwen3.8-flash`，`reasoning.effort="none"`、`max_output_tokens=7000`、`store=false`。环境可以覆盖模型与地址；本次未读取密钥配置，不能确认截图请求实际使用了哪个模型。

## 原设计的问题及处理

- 固定兜底与问题无关，却用第一人称装成综合见解：删除，失败时直接说明未完成回答；指标说明也不再代替回答。
- 正文被统一标为推断：删除数据契约中的分类字段、提示词分类要求、所有回答分类徽标及CSS。旧数据即使带分类也不会展示。
- 要求一段话覆盖全部文章，同时审核又因引用不相关拒绝整条：生成只选择能支持答案的材料，后台继续保留全部独立文章，引用界面和来源保留政策不变。
- 大量指标格式指令挤占回答任务，谨慎措辞容易退化成泛泛的方法论：先要求第一句回答具体问题，再解释依据和必要限定；指标是可选补充；不强制单段或凑字数。
- 原模型语义复核曾检查是否回应问题及证据含义；现已删除该环节以减少模型调用。回答问题及合理推理的要求继续保留在报告生成提示词中。
- 正文被删空后没有修复机会：新增一次有预算的补写，输入仍含原始问题和正文，并附具体失败原因。补写只生成回答，不生成指标；再次校验后仍为空就说明失败。取消直接停止，模型连接失败不触发额外调用。
- 正文后处理会删除书名和“根据……报告”一类短语，并压平换行：保留回答内容与段落；本地社交整理稿也不再添加万能结尾。
