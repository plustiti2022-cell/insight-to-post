Candidate Brief · 小项目考题

Insight-to-Post：从一句话想法到可分发的内容成品

  • 实习生 · AI 应用 / Agent 方向
  • 周期：1 周
  • 预计投入：3–5 天（不用天天满负荷，但我们希望是连贯的一整块思考）

这道题考的不是"能不能堆出一个 demo"，而是在真实约束下做技术判断 + 合规判断 + 产品判断的能力。

题面开始 —— 以下内容即为你的全部任务说明

一句话题目

做一个手机端优先的工具：用户输入一句话想法 → 系统自动联网检索 → 输出专业、可信、好看的数据化内容 → 分发到 X 和小红书。

背景：一个真实场景

一位分析师在通勤路上刷到一条新闻，冒出一个想法：

"AI 编程工具会不会让初级工程师岗位消失？"

她掏出手机，把这句话输进去。30 秒内她希望拿到一份有真实数据支撑、每条结论都能点回原文的分析；确认没问题之后，一键发到 X（英文受众）和小红书（中文受众），配图和排版都不用她再操心。

我们要做的，就是这件东西。

核心链路

输入(idea) → 检索(web) → 结构化(extract) → 呈现(render) → 分发(publish) → 手机端(mobile)

必须完成（Must）

做不到这些，说明项目没成立。

#要求验收标准
M1对话框输入 + 流式响应首字延迟 < 2 秒；全程让用户知道系统在干什么（在检索 / 在整理 / 在制图）
M2真实联网检索，≥ 2 类信源每条数据结论都能点击跳回原文 URL。编造或拼凑引用会被直接判负——这是硬线
M3结构化呈现，≥ 3 种模板关键指标卡片、横向对比表格、时间线演进，手机端优先设计
M4真的发布到 X走官方 API + OAuth 2.0，必须真的发出去（用测试账号即可）
M5手机端体验手机浏览器上完整可用，而且"好用"——不是缩小版桌面页
M6可复现一份 README + 一键启动脚本，别人能在 10 分钟内跑起来

应该做到（Should）

这些是加分项，也是我们判断深度的地方。

  • 引用校验：生成的引用 URL 必须真实出现在检索结果里。校验不通过就直接拒绝这条结论，而不是硬编一个链接凑数
  • 自动配图：图表渲染或 AI 生图，随内容一起产出
  • 发布前预览与回滚：能看到将要发出去的样子，发错了能删掉
  • 多平台抽象：把"发布"抽象成统一接口，将来加一个新平台不改主流程
  • 失败降级：某个信源挂了或超时，系统给出明确的降级结果，而不是白屏或瞎编

加分项（Nice）

  • 信源可信度分级（一手 / 二手 / 自媒体），并且在呈现上体现出来
  • 发布幂等：手滑连点两次，不会发出两条
  • 成本可观测：每次查询消耗多少 token、多少钱
  • 内容自带生成来源标识（可以想想：国内平台对 AI 生成的内容有什么要求？）

约束

  1. 时间 1 周。我们更看重判断，而不是功能齐全。宁可少做一个功能，也别交一个半成品。
  2. 不得使用任何平台的非官方接口、抓包、或浏览器 / 手机自动化脚本去操作账号。 这条既是保护平台，也是保护你。
  3. 如果你调研之后认为某条需求在当前条件下不该做或做不到，请明确写下来并给出依据。这不是减分项——恰恰相反，这是本题的重点之一。我们想知道你在什么情况下会说"这个不能这么做"。
一个提醒：1 周内不要碰原生 App 或 React Native——环境、真机调试会吃掉大半时间。做成手机浏览器可访问的 Web / PWA 就够了。

你需要自己解决 / 你自己决定

你需要自己解决：大模型 API（key 和账单都归你，检索 / 发布的额度也自己申请）。

你自己决定：技术栈、检索服务、托管方式、架构分层。这些选择本身就是我们要看的东西，所以不会给你框死。

交付物

  1. 可运行的仓库 + README（含架构图、启动方式、已知取舍）
  2. 一个能访问的地址，或一段 ≤ 3 分钟的录屏 demo（必须用手机视角录）
  3. 一份 ≤ 2 页的《设计决策说明》，至少回答这四个问题：
    • 你选了哪几个信源？为什么？
    • 你如何保证引用不是幻觉？
    • 小红书这一环你最后是怎么处理的？为什么？
    • 你砍掉了什么？为什么砍？

建议节奏（仅供参考，不必照搬）

天建议
Day 1跑通最小闭环（输入 → 检索 → 文字输出），同时做平台与合规调研
Day 2–3结构化 + 呈现模板，把手机端体验打磨出来
Day 4接 X 发布，处理鉴权、限流、幂等
Day 5小红书方案、补 README 和设计说明、录 demo

我们会看什么

给你一个透明的评分维度，方便你知道力气该往哪使：

维度我们在看什么
产品判断与需求收敛有没有主动砍功能、定位是否清晰、交互取舍有没有逻辑
检索质量与可信度信源是不是多元、引用是否可回溯、有没有降级处理
信息呈现专业度图表选型是否恰当、手机端观感是不是像成品
工程实现质量分层是否清晰、有没有幂等和错误处理、能不能复现
合规与平台风险判断是否意识到各平台的规则差异，并给出合理的应对
交付与沟通README 与设计说明是否清晰，能不能讲清自己的取舍

最后一句

这个项目里最难的部分，不是写代码，是判断。放手去做，有拿不准的地方就写进《设计决策说明》里——我们想看的正是你怎么拿不准。
